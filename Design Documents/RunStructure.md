# Run Structure

## Purpose

A run is a complete session of the game.

The team starts with:

> **A basic shopping cart, a basic weapon, and limited power.**

The team ends with:

> **A highly specialized, extremely powerful, and potentially uncontrollable build.**

The run should have a clear progression:

```text
Start
    ↓
Build
    ↓
Escalate
    ↓
Specialize
    ↓
Overcome Major Threats
    ↓
Final Challenge
    ↓
Victory or Failure
```

The ideal run should feel like a story of escalation.

---

# Run Length

The initial target should be:

> **20–30 minutes per run.**

This is long enough for:

* A build to develop
* Intoxication to become meaningful
* Player cooperation to evolve
* Multiple enemy types to appear
* A final challenge to feel significant

But short enough that:

> **Failure does not feel like losing an entire evening.**

The exact duration should be determined through playtesting.

---

# Run Phases

A run should consist of several phases.

```text
Phase 1 — The Start
        ↓
Phase 2 — The Build
        ↓
Phase 3 — The Escalation
        ↓
Phase 4 — The Crisis
        ↓
Phase 5 — The Finale
```

Each phase should have a different purpose.

---

# Phase 1 — The Start

## Purpose

Introduce the run.

The team should begin with:

* Basic cart
* Basic weapon
* Basic abilities
* Low intoxication
* Limited upgrades

The early game should be relatively simple.

The players should have time to:

* Relearn their controls
* Understand the current map
* Start killing enemies
* Begin forming a build

---

# Early-Game Feeling

The team should feel:

> **Weak, but capable.**

The cart should be controllable.

The Shooter should be effective enough to kill basic enemies.

The players should not immediately be overwhelmed.

The purpose of the early game is to establish:

> **What kind of run is this becoming?**

---

# First Progression Milestone

The first major milestone should happen quickly.

Possible structure:

```text
Start
    ↓
Fight Basic Enemies
    ↓
Collect Experience
    ↓
First Level-Up
    ↓
Choose First Upgrade
```

The first upgrade should begin defining the build.

Examples:

* More speed
* More fire rate
* Better braking
* More projectiles
* Better beer efficiency

---

# First Beer Decision

The first meaningful beer opportunity should happen early.

The team should be able to choose:

```text
Drink Now
    or
Save for Later
```

This introduces the central risk/reward mechanic early enough for players to understand it.

The first beer should not immediately make the game uncontrollable.

The purpose is to teach:

> **Beer makes us stronger, but changes the way we play.**

---

# Phase 2 — The Build

## Purpose

The team begins creating a build.

The players should start choosing between different strategies.

Examples:

```text
More Speed
    or
More Control
```

```text
More Damage
    or
More Fire Rate
```

```text
More Beer Power
    or
Less Intoxication
```

The run should begin developing an identity.

---

# Build Recognition

By the end of this phase, the players should be able to say:

> **"We're building toward something."**

Examples:

> "We're going for a ram build."

> "We're stacking projectile upgrades."

> "We're trying to get extremely drunk."

> "We need to improve handling before we drink more."

This is an important moment in the run.

---

# Enemy Escalation

New enemy types should be introduced gradually.

A possible structure:

```text
Early Game
├─ Chasers
└─ Small Swarms

Mid Game
├─ Ranged Enemies
├─ Heavy Enemies
└─ Environmental Threats

Late Game
├─ Disruptors
├─ Elites
└─ Complex Enemy Combinations
```

The game should introduce new problems rather than simply increasing enemy health.

---

# Phase 3 — The Escalation

## Purpose

The team's build becomes powerful.

The enemies become more complex.

The game begins testing the decisions made earlier.

The team should now have:

* Several upgrades
* A recognizable build
* Moderate or high intoxication
* More powerful enemies
* More dangerous combinations

The game should begin to feel chaotic.

But the chaos should still be readable.

---

# The Power Curve

The ideal relationship is:

```text
Player Power
      ↗
     /
    /
   /
  /________________
             Time
```

Enemy Threat should also increase:

```text
Enemy Threat
      ↗
     /
    /
   /
  /________________
             Time
```

The player should feel stronger over time.

However, the challenges should continue to evolve.

---

# Power Should Create New Problems

Example:

```text
More Speed
    ↓
Faster Ramming
    ↓
More Damage
    ↓
Harder Braking
    ↓
More Dangerous Collisions
```

Or:

```text
More Intoxication
    ↓
More Shooter Power
    ↓
More Handling Difficulty
    ↓
Greater Need for Rider Skill
```

This is the central escalation model.

---

# Elite Encounters

Elite enemies should appear during the middle and late parts of the run.

An elite encounter should provide:

* A significant threat
* A meaningful reward
* A temporary change in strategy

The team should recognize:

> **This is more dangerous than a normal enemy.**

But also:

> **This is worth fighting.**

---

# Elite Encounter Structure

```text
Elite Appears
    ↓
Team Identifies Threat
    ↓
Team Decides Whether to Engage
    ↓
Rider Creates Position
    ↓
Shooter Prioritizes Targets
    ↓
Elite Dies
    ↓
Major Reward
```

The team should sometimes have the option to avoid an elite.

This creates risk/reward decisions.

---

# Phase 4 — The Crisis

## Purpose

The team's build reaches a critical point.

By this point, the team should be:

* Very powerful
* Highly specialized
* More difficult to control
* Facing complex threats

The central question becomes:

> **Can the team handle the build they created?**

---

# Crisis Examples

## High-Speed Build

The cart is extremely fast.

The Rider has difficulty stopping.

The Shooter deals massive damage while moving quickly.

The team must maintain momentum.

---

## High-Intoxication Build

The Shooter is extremely powerful.

The cart is difficult to control.

The team must decide whether to continue drinking.

---

## Ram Build

The cart deals massive collision damage.

The Rider must constantly make dangerous approaches.

The team must avoid being surrounded after failed impacts.

---

## Precision Build

The Shooter deals massive single-target damage.

The Rider must create stable firing positions.

The team struggles when surrounded.

---

# Crisis Design

The crisis should not feel like the game suddenly cheating.

It should feel like:

> **The consequences of the team's own decisions have finally become important.**

The players should be able to look back and understand:

> **We chose this build.**

---

# Phase 5 — The Finale

## Purpose

The run needs a clear conclusion.

The team should eventually reach a final challenge.

Possible final objectives:

* Defeat a boss
* Survive a final wave
* Reach a destination
* Escape the map
* Deliver the cart somewhere
* Complete a dangerous objective

The final objective should test the entire build.

---

# Recommended Initial Finale

The best initial finale is probably:

> **A boss encounter followed by an escape sequence.**

This allows the game to test:

```text
Combat
    +
Movement
    +
Positioning
    +
Resource Management
    +
Cooperation
```

---

# Final Boss Structure

A final boss should have multiple phases.

Example:

```text
Phase 1
    ↓
Learn the Boss

Phase 2
    ↓
Boss Creates Environmental Problems

Phase 3
    ↓
Boss Adds Enemy Pressure

Phase 4
    ↓
Final Desperation
```

The team should need to use the tools they acquired during the run.

---

# Post-Boss Escape

After defeating the final boss, the team may need to escape.

This is especially appropriate for this game.

The final sequence could involve:

* Maximum enemy density
* Increasing intoxication
* Damaged cart
* Limited escape routes
* A final destination

The objective becomes:

> **You defeated the threat. Now get out.**

This creates a strong ending for a game centered around a vehicle.

---

# Run Failure

The run can end through several conditions.

## Cart Destruction

The cart reaches zero health.

---

## Team Defeat

The players are unable to continue.

---

## Failed Objective

The team fails a mission-specific objective.

---

# Failure Should Be Understandable

The team should know why they lost.

Possible reasons:

* The Rider lost control
* The Shooter ignored a priority threat
* The team became too intoxicated
* The build lacked defensive tools
* The team took too many risks

Failure should ideally produce:

> **"We can do better next time."**

Not:

> **"That was impossible."**

---

# Run Rewards

After a successful run, the team may receive permanent rewards.

Possible rewards:

* New weapons
* New carts
* New beer types
* New upgrades
* New characters
* New maps

The rewards should primarily expand the game's possibilities.

---

# Run Pacing

The run should alternate between different intensities.

```text
Low Pressure
    ↓
Combat
    ↓
Reward
    ↓
Upgrade
    ↓
High Pressure
    ↓
Recovery
    ↓
Elite Encounter
    ↓
Reward
    ↓
Major Escalation
```

The game should not remain at maximum intensity constantly.

Without periods of recovery:

> **Chaos becomes noise.**

---

# Recovery Periods

The team should occasionally receive brief moments of reduced pressure.

During these periods, players can:

* Collect rewards
* Choose upgrades
* Drink beer
* Discuss their build
* Prepare for the next encounter

These moments are important for cooperative play.

---

# The Run Should Have Peaks

A good run should have several memorable moments.

Examples:

> **First successful ram**

> **First time reaching high intoxication**

> **First elite encounter**

> **A near-death escape**

> **A powerful upgrade combination**

> **The final boss**

> **The escape after the boss**

The run should feel like a sequence of escalating stories.

---

```text

0:02
First Upgrade
    ↓
0:04
First Beer Decision
    ↓
0:07
```

---

# Run Structure and Player Agency

The run should not feel like a fixed sequence of events.

The team should make decisions that affect the run.

Possible choices:

```text
Fight Elite
    or
Avoid Elite
```

```text
Take Beer
    or
Ignore Beer
```

```text
Enter Dangerous Area
    or
Take Safe Route
```

```text
Upgrade Control
    or
Upgrade Power
```

These choices should create different runs.

---

# Branching Run Structure

Eventually, the run can have branching paths.

Example:

```text
             ┌── Dangerous Route ── Elite Reward ──┐
Start ───────┤                                      ├── Finale
             └── Safe Route ─────── Fewer Rewards ──┘
```

The team chooses its level of risk.

This works especially well with the game's central philosophy.

---

# Risk-Based Route Choices

Possible route types:

## Safe Route

* Fewer enemies
* Fewer rewards
* Lower risk

---

## Dangerous Route

* More enemies
* Better rewards
* Elite encounters

---

## Beer Route

* More beer
* More intoxication opportunities
* More handling risk

---

## Challenge Route

* Special modifier
* Significant reward

The team should be able to choose:

> **How dangerous do we want this run to become?**

---

# Run Modifiers

Each run can eventually contain modifiers.

Examples:

## Wet Floor

Reduced traction.

---

## Happy Hour

Beer appears more frequently.

---

## Heavy Traffic

More enemies spawn.

---

## Last Call

Intoxication provides greater bonuses.

---

## No Brakes

The cart's braking is significantly reduced.

Modifiers should change the run's strategy.

---

# Run Structure and Build Identity

The run should allow the team to discover a build rather than simply follow a predetermined plan.

Example:

```text
Early Upgrade:
Extra Projectile
    ↓
Later Upgrade:
Piercing Shot
    ↓
Later Upgrade:
Momentum Shot
    ↓
Rider Upgrade:
Turbo Engine
    ↓
Build Identity:
High-Speed Projectile Build
```

The build emerges through the run.

---

# The Run's Narrative Arc

The game should have a simple mechanical narrative:

```text
We Found a Shopping Cart
        ↓
We Started Fighting
        ↓
We Got Stronger
        ↓
We Drank More
        ↓
We Became Powerful
        ↓
We Lost Control
        ↓
We Somehow Survived
```

The mechanics should naturally create this story.

---

# Run Structure Success Criteria

The run structure is successful if:

```text
The beginning is accessible
        AND
The build develops naturally
        AND
New threats are introduced gradually
        AND
The team becomes noticeably stronger
        AND
Power creates new risks
        AND
The run contains memorable peaks
        AND
The finale tests the entire build
        AND
Failure feels understandable
```

---

# Final Run Structure Principle

The run should not simply be:

> **Fight enemies until the timer ends.**

It should feel like:

> **A journey from a barely functional shopping cart to an absurd, overpowered, drunken war machine that must survive the consequences of its own evolution.**

The ideal run structure is:

```text
Weak
    ↓
Capable
    ↓
Specialized
    ↓
Powerful
    ↓
Chaotic
    ↓
Desperate
    ↓
Legendary
```

The team should begin the run asking:

> **How do we survive?**

And end it asking:

> **How are we still alive?**
